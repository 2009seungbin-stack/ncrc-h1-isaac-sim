P1 — Terminal/cleanup streaming ACK race: FIX VERIFIED.
runner.validate saves COMPUTE_COMPLETE_RETRIEVE_AND_STOP_ALLOCATION before
execute.finally performs preserve/restore/guard and requests a new cleanup
release token. helper.control exits immediately on that terminal stage and
releases its lease in finally; it therefore cannot acknowledge the subsequent
cleanup token. CPU mocked control reproduced terminal return with acknowledge
call_count=0 and release_lease call_count=1. If the helper reads the terminal
stage in that gap, the runner's 30-second ACK wait reports RECOVERY_FAILED after
otherwise complete validation. Partial/error stages have the same possibility.
Owner repaired runner.validate to store compute_completed=true and the
non-terminal COMPUTE_FINISHED_CLEANUP_PENDING stage. Failure stores the
non-terminal ERROR_CLEANUP_PENDING stage. Actual terminal complete/partial is
published only after the cleanup release ACK; archive completeness is assessed
after that publication. Two new CPU integration fixtures cover success and error
ordering; runner43 tests pass. There is no controller rearm or fabricated ACK.
Actual deadline recovery after11700 still requires observed helper/resumer
receipts; any missing current ACK correctly remains an incomplete recovery.

P1 — Nested forced-stop allowance: FIX VERIFIED at final delta.
Wrapper monitor/launch-error cleanup invokes runner.stop_process on the runner;
that routine INT30s -> TERM15s -> KILL5s escalates to KILL at45s. The runner itself
uses the same sequence to stop its owned GPU child before preserve/restore/archive.
In the worst case the wrapper can KILL a normally cleaning-up runner at45s while
the child cleanup still consumes its45-50s allowance, before reward restoration.
Owner added separate graceful_stop_runner with SIGINT120s, TERM15s, KILL5s,
bounded by confirmed-OFF deadline minus60s. Current owned member identities and
the leader's exact original argv are checked immediately before every signal.
Both bootstrap failure and monitored finally use this routine, without helper
rearm or numeric signaling of unrelated GPU groups. Four new CPU fixtures cover
a runner finishing normal nested cleanup after60s without escalation, fresh
identity checks at every escalation, changed-argv refusal and the final deadline
bound. All22 launcher tests pass; no actual Linux signals were executed.
