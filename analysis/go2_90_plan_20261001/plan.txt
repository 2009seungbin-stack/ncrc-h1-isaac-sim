Go2 공식 90점 이상 계획 — 2026-10-01
상태: 계획과 오프라인 계산만 작성. 서버 가동·학습·제출 없음. 후보 파일은 아직 미학습.

1. 목표와 현실적인 난도
마지막 확인 공식 점수 88.14 = 시뮬레이션 58.14 + 설계 20 + 보고서 10.
90.00에는 시뮬레이션 60.00, 즉 +1.86이 필요하다. 여유 목표는 90.30.
공식 시나리오별 상승 예산의 한 예:
G1 전진·후진 추종: 8.80 → 9.00 (+0.20)
G2 전방향 추종: 8.66 → 9.00 (+0.34)
G3 요철: 11.69 → 12.00 (+0.31)
G4 경사: 8.79 → 9.00 (+0.21)
G5 계단: 8.56 → 9.00 (+0.44)
G6 밀침: 5.79 → 6.00 (+0.21)
G7 도메인 랜덤화: 5.85 → 6.00 (+0.15)
합계 58.14 → 60.00. 이것은 목표 배분이며 결과 예측이 아니다. 다른 항목이 보충해도 된다.
우선순위: 계단의 부족분 0.44, 전방향 0.34, 가중치 20% 요철 0.31.
전체 +1.86에 비해 계단만의 최대 추가 가능 점수도 1.94이므로, 한 항목만 극대화하는 것은 취약하다.

2. 근사식의 한계를 먼저 반영
이전 두 정책으로 맞춘 고정 c 모형의 이론적 총점 상한은 89.42098.
따라서 해당 근사식으로 90을 인증할 수 없다. 공식 대회에 89.42라는 상한이 있다는 뜻도 아니다.
0.905 비율 모형을 고정하면 자체 3축 점수 66.29834가 조건부 90점 지표다.
현재 64.19175에서, 다른 조건·생존이 같다고 가정할 때 전 축 RMSE를 일괄 37.3% 줄여야 한다.
회전 축만 줄이면 84.1%가 필요하다. 이 모형에서는 회전만으로 90.3에 도달할 수 없다.
이 수치는 가정에 대한 민감도 계산이다. 근사 계수 c를 조절하거나 실제 학습 성과로 보고하지 않는다.
공식/자체 평가 차이의 원인에는 미확인 공식 생존·추종 정의·명령·지형이 포함될 수 있다.
공식 결과 한 회를 더 확보해 근사식의 예측 오차와 시나리오별 실제 상승을 갱신한다.

3. 실행 순서와 30시간 상한
남은 서버 시간은 마지막 확인 기준 51시간25분이다. 현재 단계 30시간, 후속 공식 결과 반영에 21시간25분을 남긴다.
Go2 과거 관측 4.8초/iteration으로 산정한 예상이며, 시작·검증·백업 시간과 실제 속도를 따로 기록한다.
매 단계 잔여 예산을 재계산하며, 시간 부족 시 조건부 탐색을 줄여 최종 검증 시간을 보장한다.

A. 공통 진단: 1.5시간
현재 C0 5500과 원본 파일·제출 묶음을 별도 보존하고 SHA-256을 기록한다.
제공된 wrapper/import/README로 resume·seed·num_envs의 허용과 동작을 확인한다.
train.py --help는 정리 hook을 실행할 수 있으므로 확인 수단으로 사용하지 않는다.
50~100회 재개 시험에서 std·손실·물리 경고를 확인한다. C0는 5528회에서 중단됐으므로 재개 성공을 가정하지 않는다.
실패하면 같은 초기 조건으로 만든 새 공통 부모 2500회 이내를 최대 4시간 복구 예산에서 확보한다.
복구도 불안정하면 C0 재개를 버리고 scratch 대조군/후보 수를 줄인다. 알고리즘·optimizer·std를 임의 수정하지 않는다.
noise ON 기준 G1/G2/G5와 noise OFF 진단을 비교한다. OFF 결과는 공식 예상 점수로 쓰지 않는다.

B. 보상 2×2 탐색: 7.5시간
제공 REWARD_WEIGHTS의 값만 변경한다. 이미 별도 파일로 만든 후보:
F00 대조: track_ang_vel_z_exp 0.75, action_rate_l2 -0.010
F10 회전: track_ang_vel_z_exp 1.50, action_rate_l2 -0.010
F01 매끄러움: track_ang_vel_z_exp 0.75, action_rate_l2 -0.015
F11 조합: track_ang_vel_z_exp 1.50, action_rate_l2 -0.015
track_lin_vel_xy_exp 2.0과 나머지는 고정한다.
각각 같은 공통 부모에서 추가 1200회, 기본 6144 env의 순차 실행. 순수 학습 약6.4시간.
8192/12288 env는 과거 contact patch capacity 초과 기록이 있어 이번 기본 계획에서 제외한다.
동시 학습 두 개도 과거 총 처리량이 떨어졌으므로 사용하지 않는다. 처리량 개선은 점수 개선의 근거로 삼지 않는다.
300회는 발산 검사, 1200회는 후보 선별이다. 재개 시 지형 커리큘럼 초기화를 동일하게 맞춘다.
짧은 학습에서 지형 적응이 덜 됐다면 최종 실패로 단정하지 않는다.
7개 시나리오·같은 reset seed로 평가하며 회전 효과, action 벌점 효과, 두 항의 상호작용을 분리한다.
회전 오차 MSE의 약78.5%는 회전 명령0 구간이다. 이 구간의 변동을 20~30% 줄이는 것을 1차 진단 목표로 삼는다.
평균 회전 오차 편향은 약3.8%뿐이라 평균 선회값만 맞추는 접근은 우선순위를 낮춘다.
매끄러움 강화가 추종 지연·회복 실패·탐색 억제를 유발하면 보상 합이 높아도 탈락시킨다.

C. 조건부 계단·요철 탐색: 2.5시간
B에서 추종은 좋아졌지만 계단·요철의 다리 걸림/과한 상하 운동이 남은 경우에만 실시한다.
승자와 같은 부모를 기준으로 한 항씩 최대 두 후보를 고른다:
  lin_vel_z_l2 -3.0 → -2.0 또는 feet_air_time 0.01 → 0.03(필요시 0).
이는 대회가 제공한 기존 보상 값만의 변경이다. 동시에 두 항을 바꾸지 않는다.
각 700~800회는 진단용. 효과가 애매하면 더 복잡한 설정을 추가하지 않고 B의 후보로 돌아간다.
밀침·도메인 랜덤화 생존과 계단 추종의 교환을 확인한다. 과거 D1의 ang_vel_xy 강화를 반복하지 않는다.
이 단계가 불필요하거나 부모 재개가 불안정하면 예산을 독립 확인/복구에 넘긴다.

D. 독립 확인 학습과 최종 검증: 14.5시간
새 공통 학습 seed를 사용하되 제공 CLI가 허용할 때만 설정한다.
후보 하나는 scratch에서 최대5500회 연속 학습, 원본 보상 대조는 scratch에서4000회 연속 학습.
두 정책의4000회 스냅샷을 비교해 같은 예산에서 보상 효과를 확인한다. 후보5500과 대조4000의 차이를 순수 보상 효과라고 주장하지 않는다.
순수 학습 약12.67시간, 검증·export·백업 등에 약1.83시간.
기존 C0 5500은 실제 제출 기준 정책으로 별도 비교한다. 기존 C0 2000/4000은 평가 JSON만 있으므로 재개용 checkpoint로 계획하지 않는다.
후보를4000회에서 멈췄다가 재개하면 커리큘럼이 다시 초기화될 수 있으므로 처음부터 연속5500회 한도로 계획한다.
100회 단위 저장본을 cleanup 영향 밖에 보존하며 actor/critic/optimizer finite, std 유효성, 물리 경고를 확인한다.
중간 평가가 동시에 실행되어 학습 자원을 잠식하지 않도록 순차 실행과 별도 시간 계측을 사용한다.
4000/4500/5000/5500 등 평가 가능한 저장본에서 검증 기준으로 선택한다. 마지막 checkpoint가 최고라는 가정은 하지 않는다.
5528회 근처 재중단에 대비해 앞선 건강한 저장본과 현재 C0 정책을 확보한다.

E. 실패 복구: 최대4시간
새 부모 재학습, 재개 실패, export·검증 재시도에만 배정한다. 예산은 A~D와 중복 계산하지 않는다.
30시간을 다 쓰고도 공식 90점이 입증되지 않으면 남은21시간25분을 새 공식 시나리오 결과에 맞춰 배분한다.

4. 검증의 빈틈 메우기
기존 자체 평가 조건은 보존하여 과거 결과와 계속 비교한다. 아래는 별도 이름의 추가 진단으로 남긴다.
계단: 기본12cm뿐 아니라10/12/15cm, 오르기·내리기와 전환 구간을 확인한다.
경사: 자체 evaluator는 slope_deg를 radians로 바꾸지만 upstream terrain은 rise/run ratio를 받는다.
명령상20도라고 실제표면20도가 되는 것은 아니다. ray/표면 높이로 실제 경사를 확인한 경계 조건을 추가한다.
피라미드의 위치별 기울기·양자화도 있으므로 단순 숫자 치환만으로 실제20도를 인증하지 않는다.
명령 전환: 기존 transient_s0.5 외에0 진단을 추가해 전환 후 첫0.5초의 흔들림과 복구를 본다.
seed: 선별 A=[103,280,512,991], 최종 보류 B=[137,389,743,1201]. B는 최종 선택 후 확인에 사용한다.
terrain seed1234가 고정이므로 네 reset seed가 네 지형 배치를 뜻하지 않는다. 추가 지형 배치 검증은 현재 evaluator 지원 여부를 별도로 확인해야 한다.
도메인 랜덤화 startup 샘플도 reset seed만 바꿨다고 새 샘플이 된다고 가정하지 않는다.
7개 본 평가에서 현재의 관측 생존 성적(각512/512)을 유지하고, 강한 밀침·경계 지형에서 회복 실패가 늘지 않는지 확인한다.
관측 무탈락은 공식 평가 생존율1이나 일반화 보증이 아니다.
3축 추종이 좋아지는 동시에6축·축별·시나리오별 회귀를 점검한다. 공식 축이 식별되지 않아6축도 공식 점수로 단정하지 않는다.

5. 승격·제출 기준과 피드백 분기
보상 합이 아닌 추종·생존·독립 재학습의 일관성으로 선별한다. 한 시드의 최고값을 선택 근거로 쓰지 않는다.
비율 근사상 자체3축66.30은 조건부 목표이나 이를 통과해도90을 보증하지 않는다.
반대로 고정 c 근사상90이 안 나온다는 이유만으로 후보를 탈락시키지도 않는다.
제출 전 정책·env·보상 파일·checkpoint 해시, export load,7개 결과, 영상, 보고서를 일치시킨다.
보고서에는 회전 등 고급 보상까지 실제 변경값과 실험 근거를 명시한다. 기존 설계20/보고서10의 재확보도 확인 대상이다.
최종 달성 기준은 실제 공식 시뮬레이션60.00 이상과 설계·보고서30.00이다.
다음 공식 결과가 오면 사전 예측과 실제 시나리오 상승을 비교:
  계단·요철 상승 부족 → 남은 예산을 지형 보상 한 항과 경계 검증에 집중.
  평지·전방향 상승 부족 → 회전/선속도 추종과 전환 응답의 독립 탐색.
  전체 균일한 격차 지속 → 생존·추종 정의/평가 범위 차이 확인, 근사식을 다시 추정.
현재 제출 정책보다 독립 검증이 나쁘면 교체하지 않는다. 다음 라운드에서 다시 시도할 수 있게 원본을 보존한다.
